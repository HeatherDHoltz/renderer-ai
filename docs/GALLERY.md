# Real render gallery

Every image below is output from this Rust renderer and was visually inspected. No image-generation model was used to create render evidence. Commands run from the repository root; Cargo's release profile is used throughout. Scene defaults specify camera, seed, materials, lights, depth, and output conversion. Auto workers depend on the machine; same-build images are independent of worker count.

The [gemstone gallery](GEMS.md) adds six transmitting gems and three chatoyant stone variants, using four credited online jewel meshes and two supplemental generated shapes. Its labeled panels and moving-light GIF are assembled from real Rust-rendered frames.

![Hero](../gallery/hero.png)

The still life combines a generated indexed torus, a faceted OBJ, rough gold, ideal glass, ceramic, slate, soft area shadows, and a synthetic HDR environment. The scene is AI-assisted and the model is a direct-light baseline, with the limitations in [PHYSICAL.md](PHYSICAL.md). Glass tint is per interface rather than absorption. The dark glass/metal regions are consistent with missing indirect transport, not evidence of a full path tracer.

![Branching garden](../gallery/garden.png)

The garden uses real cylinder and ellipsoidal leaf instances generated by a bounded L-system; it is stylized geometry, not a scanned plant. The checked seeds and configs reproduce it without external services.

The gallery retains modest-size diagnostic images rather than hiding sampling artifacts: one-sample edges alias, very distant procedural checkers alias without prefiltering, and Monte Carlo direct lighting retains some noise. Use documented sample controls to explore those tradeoffs. Bulk PNG/HDR files and sequences stay in ignored `output/`.
